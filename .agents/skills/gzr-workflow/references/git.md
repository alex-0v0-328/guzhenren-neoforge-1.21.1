# Git 与 GitHub

- 只有用户要求提交时进入提交路径。先按独立目的分组，每组带自己的测试、provider 和生成资源。标题格式、选择要求、推送约定统一读 `AGENTS.md` §4.1，不在本技能重复维护。
- 暂存使用明确文件与审阅过的 `git apply --cached` 补丁；共享文件不能整份加入错误分组。用 `git diff --cached` 审阅，不撤回工作区内容来模拟中间版本。
- 独立验证中间状态需要时，把 `git write-tree` 的索引快照导出临时主模组副本；依赖从已有明确路径配置，禁止扫描排除目录。验证完成检查最终工作区与原快照，避免丢失 Alex 同期修改。
- 获取英文标题选择后才 commit。可将 2–3 个标题放入支持文本选择的异步问题中；名称回复未到时继续独立工作，但不代选提交。
- 推送使用当前 origin 和明确分支；不强推、不重写既有历史、不自动修改重定向 remote。推送前检查远程前进与本地差异，冲突保留双方工作后处理。
- GitHub 集成负责查仓库、PR、Checks/Actions 和远程 SHA；Git commit status 与 Actions/check-runs 分开查询，空 status 不能宣称 CI 通过。没有 PR 请求时不制造 PR。
- 最终报告每个提交 SHA、标题、推送状态及实际 CI 状态。不添加 AI 署名或会话尾注。
