# 审查与清理

- 读 `git diff HEAD` 和未跟踪文件，按目的建立变更覆盖表，再检查调用上下文。区分新增缺陷、既有相邻缺陷、未决设计；每条发现提供触发条件、路径/行号、影响与最小修复。
- 数值审查整个表达式：饱和加法不保证后续乘法安全；先夹值再加减可能改变最终符号。检查零、负值、MIN/MAX 与普通区间，避免用测试复制同一错误公式。
- 生命周期检查 goal 中断、逃跑/寻路失败、目标死亡、伤害拒绝、NBT 恢复和晚追踪。停止一个动作时必须保证有可达的后续状态。
- 已授权修复时先保存复现证据，补必要回归，再最小修复。大范围重命名/格式化不是清理的默认动作；外部类型签名和刻意保留的行为以领域参考为准。
- 需要结构查询时调用 ast-grep run 并限定 Java 文件或目录；其位置是语法匹配，不是类型证明。遇到库 API 不确定性查固定依赖源码。
- 清理文件前核对引用、Git 跟踪、用途和活动占用，备份并核验 hash。不运行全库 git clean，不动运行 mods、存档或最新测试证据。
- 不重建冗长审查模板。最终汇总实质发现、修改与实际验证，保留未验证边界。
